# LLM-модуль: объяснение кредитного решения

## Назначение и статус
Кнопка «Объяснить простыми словами» позволяет клиенту получить понятное объяснение от ИИ по уже принятому кредитному решению.

**⚠️ Статус реализации (MVP):** Бэкенд-модуль LLM полностью реализован, протестирован и доступен через Swagger UI (`POST /applications/{id}/explain`). Из-за ограничений по времени (хакатон) и технических нюансов, интеграция модуля в клиентский интерфейс (Frontend) вынесена в Roadmap. Основной сквозной кредитный процесс при этом работает без блокировок.

**Важно:** LLM не принимает кредитных решений. Решение формирует детерминированный скоринг (`backend/app/services/scoring.py`). Модель выполняет исключительно роль переводчика с банковского языка на человеческий.

## Архитектура и безопасность
- **Изоляция:** Модель запускается в отдельном Docker-контейнере (`profile: llm`) через `llama.cpp`.
- **OpenAI-совместимость:** Используется стандартный протокол `/v1/chat/completions`. Провайдер легко заменяется через переменные `LLM_URL` и `LLM_MODEL`.
- **Защита от галлюцинаций (Guardrails):**
  1. В промпт передаются только числа и статусы из БД. Свободный текст клиента (поле `purpose`) блокируется.
  2. Следующий шаг («подписать документы», «подать заново») определяется кодом, а не моделью.
  3. Включен фильтр запрещенных фраз (если модель говорит «деньги выданы», а статус заявки не `DISBURSED`, ответ отбрасывается).
- **Graceful Degradation:** Если модель недоступна, загружается или отвечает дольше 90 секунд, клиент получает заранее подготовленный шаблонный текст. Основной процесс не блокируется.

## Модель
- **Название:** T-lite-it-2.1 (T-Technologies).
- **Лицензия:** Apache 2.0 (Open Weights).
- **Формат:** GGUF (Q4_K_M).
- **Ресурсы:** Требует ~6-8 ГБ свободной ОЗУ. Запускается на CPU, не требует дискретной видеокарты.

## Запуск и проверка (через Swagger/Postman)
1. Запуск с ИИ: `docker compose --profile llm up --build -d` (при первом запуске скачает веса с Hugging Face).
2. Проверка статуса: `GET /llm/status` (возвращает `ready`, `loading` или `unavailable`).
3. Запрос объяснения: `POST /applications/{id}/explain` (для заявки, по которой уже принято решение).
