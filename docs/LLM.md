# LLM-модуль: объяснение кредитного решения

## Назначение
Кнопка «Объяснить простыми словами»: по уже принятому решению модель пишет клиенту
3-4 предложения - что решил банк, почему и что можно сделать дальше.

**LLM не принимает решений.** Решение формирует правиловый скоринг
(`backend/app/services/scoring.py`). Модель только пересказывает результат.

## Архитектура
```
Браузер -> backend (FastAPI) --LLM_URL--> контейнер llm (llama.cpp server, модель с открытыми весами)
```
- Backend знает только адрес `LLM_URL` и OpenAI-совместимый протокол (`/v1/chat/completions`, `/health`).
  Модель можно заменить или вынести на другой сервер, поменяв одну переменную окружения.
- Контейнер `llm` лежит в профиле `llm`: обычный `docker compose up` его не запускает и ничего не скачивает.
- У backend нет `depends_on` на `llm`: основной кредитный сценарий от ИИ не зависит.

## API
`GET /llm/status` - доступна ли модель. Всегда отвечает 200, не зависит от `/health`.

| `status` | `available` | Значение |
|---|---|---|
| `ready` | true | модель готова отвечать |
| `loading` | false | контейнер запущен, модель загружается в память (llama.cpp отвечает 503) |
| `unavailable` | false | LLM не запущена или недоступна |

Фронтенд по `available` включает или отключает кнопку ИИ.

`POST /applications/{id}/explain`

| Код | Значение |
|-----|----------|
| 200 | `{"text": "...", "source": "llm" \| "fallback", "model": "..." \| null}` |
| 404 | заявка не найдена |
| 409 | решение по заявке ещё не принято (сначала `/process`) |

`source = "fallback"` означает, что модель недоступна, ещё грузится или не уложилась в таймаут,
и показан шаблонный текст.

## Безопасность и надёжность
- В промпт попадают только числа и коды из БД. Свободный текст пользователя (`purpose`) не передаётся.
- Все расчёты (прибыль, доля платежей) делает код, не модель.
- Следующий шаг для клиента («подписать документы», «подать новую заявку» и т.д.) определяет код по решению и статусу заявки и передаёт модели готовым. Модель не придумывает шаги процесса.
- Ответ модели проверяется: если она утверждает, что средства уже выданы или что делать ничего не нужно, а заявка ещё не в статусе DISBURSED, ответ отбрасывается и показывается шаблонный текст.
- Ответ приводится к одному абзацу (переносы строк убираются).
- Если модель не готова, запрос к ней не отправляется, сразу возвращается шаблонный текст.
- Таймаут ответа задаётся `LLM_TIMEOUT_SECONDS` (по умолчанию 90 с).
- Ответ кэшируется в памяти по id решения.
- Новых Python-зависимостей нет (стандартная библиотека).

## Запуск
Без ИИ (как у всех): `docker compose up --build`.

С ИИ: `docker compose --profile llm up --build`.
- Первый запуск скачивает модель с Hugging Face (несколько ГБ, нужен интернет), дальше она лежит в томе `llmmodels`.
- Повторные запуски сначала берут модель из кэша без сети (`--offline`), и только если её там нет, идут в интернет.
- Загрузка модели в память занимает от десятков секунд до нескольких минут. Пока она идёт, `/llm/status` возвращает `loading`.
- Ориентир по ресурсам: модель 8B в квантизации Q4 требует порядка 6-8 ГБ свободной оперативной памяти.
  В Docker Desktop (Windows) проверьте лимит памяти для WSL2.
- Нет интернета и нет кэша: контейнер `llm` завершится, остальной проект работает без ИИ.

## Переменные окружения
| Переменная | По умолчанию | Описание |
|---|---|---|
| `LLM_URL` | `http://llm:8080` (в compose) | адрес сервера с OpenAI-совместимым API |
| `LLM_MODEL` | `t-lite-it-2.1` | имя модели в запросе |
| `LLM_TIMEOUT_SECONDS` | `90` | таймаут ответа |
| `LLM_HF_REPO` | `t-tech/T-lite-it-2.1-GGUF:Q4_K_M` | репозиторий и квант модели для скачивания |
